# PFC Newsroom

Single source of truth for the Pressed Fresh Collective newsroom on
pressedfreshcollective.com. This repo IS the newsroom: the data file,
every image for post-migration releases, the Squarespace code block,
and the publish tooling all live here. If it isn't in this repo, it
isn't published.

## How it works

```
Team drops release + images  ->  Claude formats & pushes to this repo
        (Drive folder)              (routine or a normal session)
                                          |
                                    GitHub Pages serves
                                    pfc-newsroom-data.js + images/
                                          |
                          Squarespace code block loads it on page view
                          (the code block is NEVER edited after setup)
```

- `pfc-newsroom-data.js` — all releases, newest first, as
  `window.PFC_RELEASES=[...]`. Loaded by the Squarespace code block via a
  script tag (script tags dodge the CORS problems that killed fetch()
  against Squarespace file storage).
- `images/<release-id>/` — images for releases published after the
  Prowly migration (29 Jul 2026). Entries reference them by relative
  path (`images/2026080301/hero.jpg`); the code block resolves those
  against the GitHub Pages URL. Pre-migration images are still
  hot-linked from Prowly's S3 (backups of all of them exist as two zips
  in `~/claude code/pfc-newsroom/` and in the PFC Newsroom Handoff
  Drive folder, in case Prowly is ever cancelled).
- `newsroom-code-block.html` — the ONE block pasted into the Squarespace
  Code Block. After setup it never changes; publishing is just pushing
  to this repo.
- `index.html` — auto-generated live preview of the newsroom, served by
  GitHub Pages at the repo's Pages URL. Check a release here before/
  without touching the Squarespace page. Regenerated by `publish.sh`;
  never edit by hand.
- `queue-state.json` — the intake routine's memory of what it has
  already processed. Living here (versioned, single copy) replaces the
  duplicate state files that used to accumulate in Drive.

## Publishing a release (team routine)

1. Drop one folder per release into the Drive folder
   **PFC Newsroom Handoff → incoming/** named `YYYY-MM-DD-artist-title`,
   containing the final press release doc and every image
   (first/hero image named so it's obvious, e.g. `hero.jpg`).
2. That's it. The hourly routine picks it up, formats the entry
   (pfc-newsroom-entry conventions - no em dashes), saves the images
   under `images/<id>/`, validates, pushes, and Slacks the live link to
   #newsroom-queue.
3. Live within ~10 minutes of the push (GitHub Pages CDN cache).

Manual/urgent path: ask Claude in any session to "add this to the
newsroom and publish", or run `./publish.sh "Add release: ..."` after
editing the data file.

## Safety rails

- `tools/validate.py` runs before every publish: parse check, unique
  ids, dates newest-first, every referenced image file exists, no
  base64 blobs, em-dash check on post-migration releases. Publish is
  blocked on errors.
- Every publish is a git commit: `git log` is the audit trail,
  `git revert` un-publishes a mistake in seconds.
- Nothing here can break the Squarespace site itself - worst case the
  newsroom section shows its "could not load" message and reverting the
  bad commit fixes it.

## Do not

- Do not edit the Squarespace code block to publish (that was the old
  workflow - publishing is now only a git push).
- Do not upload data files to Squarespace file storage anymore.
- Do not hand-edit `index.html` (generated) or commit base64 images
  into the data file (validator will block it).
